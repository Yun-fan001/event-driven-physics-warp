一、总体架构说明
------------------------------------------------------------
仿真代码的核心「数据流」是:
  MuJoCo环境 → 采集循环 → .npz文件 → Dataset加载 → 模型训练/推理

真实机器人的数据流替换为:
  ROS2 Topic订阅 → 采集循环(时间对齐) → .npz文件 → Dataset加载 → 模型推理
                         ↓
               (可选的ros2 bag记录)

需要替换/新建的核心文件:
  [新建] real_robot_collector.py   ← 真实数据采集主脚本
  [新建] ros2_sensor_bridge.py     ← ROS2传感器接口封装
  [可选] launch/collect_stick_slip.launch.py ← ROS2 launch 文件
  [适配] dataset.py                ← 如果数据格式有变化
  [不变] models/ train_step2.py run_experiments_step3.py plot_results_step3.py

注意: 修复后的仿真 pipeline 中, 模型输入仅含 视觉+力(3维)+本体位置,
      不含速度通道(缺陷5修复)。实机采集同样只需保存这些字段 +
      用于自动标注的 force/velocity 传感器信号。npz 格式:
      frames / forces / velocities / proprio(任务相关) / contact_states_gt
      / contact_states_auto / 事件标记 / 元数据。dt 以实际采样周期为准。

二、摄像头适配 (Camera, ROS2)
------------------------------------------------------------
ROS2 图像消息: sensor_msgs/msg/Image (rclpy)
预处理器: cv_bridge 的 CvBridge (ros-jazzy-cv-bridge)

基础订阅代码 (ros2_sensor_bridge.py 中):

```python
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import Image
from cv_bridge import CvBridge
import numpy as np

class CameraSubscriber(Node):
    def __init__(self, topic: str = "/camera/color/image_raw",
                 encoding: str = "rgb8"):
        super().__init__("camera_subscriber")
        self.bridge = CvBridge()
        self.latest_frame = None
        self.latest_timestamp = None
        self.sub = self.create_subscription(
            Image, topic, self._callback, qos_profile=10
        )
        self.encoding = encoding  # rgb8 / bgr8 / mono8

    def _callback(self, msg: Image):
        # ROS2: 使用 msg.header.stamp (builtin_interfaces/Time)
        self.latest_timestamp = (msg.header.stamp.sec
                                 + msg.header.stamp.nanosec * 1e-9)
        cv_image = self.bridge.imgmsg_to_cv2(
            msg, desired_encoding=self.encoding)
        self.latest_frame = np.asarray(cv_image)

    def get_frame(self):
        return self.latest_frame, self.latest_timestamp
```

相机型号适配项 (与 ROS1 版一致, 仅 driver 名称变化):
| 型号            | 默认topic                   | 分辨率   | encoding | 备注 |
|----------------|----------------------------|----------|----------|------|
| RealSense D435i| /camera/color/image_raw    | 640x480  | rgb8     | realsense2_camera(ROS2); 含IMU可辅助时间戳 |
| RealSense D415 | /camera/color/image_raw    | 1280x720 | rgb8     | 卷帘快门, 快速运动有拖影 |
| ZED 2          | /zed/zed_node/rgb/image_rect_color | 1280x720 | bgra8 | zed-ros2-wrapper |
| 普通USB相机     | /image_raw                 | 640x480  | bgr8     | usb_cam(ROS2) |

三、力觉传感器适配 (ROS2)
------------------------------------------------------------
六维力/力矩传感器 (ATI Nano17 量级) 常见 ROS2 driver:
  - ATI: ati_ft_sensor / netft_utils (需确认具体驱动包)
  - 通用: 读取 geometry_msgs/msg/WrenchStamped

```python
from geometry_msgs.msg import WrenchStamped

class ForceSubscriber(Node):
    def __init__(self, topic: str = "/ft_sensor/wrench"):
        super().__init__("force_subscriber")
        self.latest_wrench = None
        self.latest_timestamp = None
        self.sub = self.create_subscription(
            WrenchStamped, topic, self._callback, qos_profile=10)

    def _callback(self, msg: WrenchStamped):
        self.latest_timestamp = (msg.header.stamp.sec
                                 + msg.header.stamp.nanosec * 1e-9)
        self.latest_wrench = np.array([
            msg.wrench.force.x, msg.wrench.force.y, msg.wrench.force.z,
            msg.wrench.torque.x, msg.wrench.torque.y, msg.wrench.torque.z,
        ])
```

四、本体感知 (关节状态)
------------------------------------------------------------
sensor_msgs/msg/JointState 订阅机械臂关节位置 (与仿真 proprio 对齐):

```python
from sensor_msgs.msg import JointState

class JointStateSubscriber(Node):
    def __init__(self, topic: str = "/joint_states"):
        super().__init__("joint_state_subscriber")
        self.latest_positions = None
        self.sub = self.create_subscription(
            JointState, topic, self._callback, qos_profile=10)

    def _callback(self, msg: JointState):
        self.latest_positions = np.asarray(msg.position, dtype=np.float32)
```



五、时间同步 (本课题成败关键)
------------------------------------------------------------
优先级 (与规划一致):
1. 硬件触发: 相机 GPIO ↔ 力觉采集卡触发线 (最优, 微秒级)
2. ROS2 message_filters + 同机采集 + 事后标定固定偏移:
   - camera (30 Hz) 与 force (500-1000 Hz) 非同频, 用
     message_filters.ApproximateTimeSynchronizer 或 TimeSynchronizer
   - 最低满足验收容差: 事件时刻 ±5 帧
3. 采集后校验: 对齐误差 > 200ms 时检查 NTP/PTP 时钟同步

```python
import message_filters
from sensor_msgs.msg import Image
from geometry_msgs.msg import WrenchStamped

cam_sub = message_filters.Subscriber(self, Image, "/camera/color/image_raw")
ft_sub = message_filters.Subscriber(self, WrenchStamped, "/ft_sensor/wrench")
ts = message_filters.ApproximateTimeSynchronizer(
    [cam_sub, ft_sub], queue_size=30, slop=0.05)  # slop 按实测调
ts.registerCallback(self._synced_cb)
```

六、实机采集执行清单 (Task 1 Slip-Onset)
------------------------------------------------------------
1. 力觉零偏标定: 无接触 3σ 定阈值 (采集前必做)
2. 轨迹设计: 机械臂慢速三角波推动物块 (~0.02 m/s), 与仿真一致
3. 自动标注阈值按实机传感器噪声重新标定 (params_record.md 记录)
4. 事件标签 = 自动标注 + 人工抽检 10%
5. 每次实验全量备份 + 参数记录 (摩擦材质/速度/法向力)
6. Sim2Real 验证: 仿真模型 zero-shot 实机推理 → F1 gap → 少量实机 fine-tune

七、适配检查清单 (ROS2 版, 实机实验前逐项确认)
------------------------------------------------------------
□ 1. ROS2 环境:  source /opt/ros/jazzy/setup.bash; ros2 topic list
□ 2. 机械臂驱动: ros2 topic echo /joint_states --once
□ 3. 力传感器驱动: ros2 topic echo /ft_sensor/wrench --once
     (用手按压传感器, 观察读数是否变化)
□ 4. 相机驱动: ros2 run rqt_image_view rqt_image_view
□ 5. 时间戳对齐测试: 同时记录 camera.header.stamp 与 wrench.header.stamp
□ 6. 力传感器零偏标定: 无接触时读数 < 0.5N (3σ), 严重零漂则后处理去偏
□ 7. 控制频率与传感器频率匹配: 控制回路 > 传感器最低频率
□ 8. 紧急停止: 机械臂急停 + 软件急停(最大力阈值/速度限位)
□ 9. 采集 1 条测试轨迹: real_robot_collector.py 单条 → visualize_step2.py 可视化
□ 10. 自动标注精度验证: event_annotation_v2.py + 人工检查事件标记
□ 11. Zero-Shot 测试: 仿真 checkpoint 在实机数据上推理, 记录 Sim-to-Real Gap

八、常见故障排查 (ROS2)
------------------------------------------------------------
Q: 时间戳全为 0?
A: 检查 msg.header.stamp 是否填充; 使用 sim_time 时需 /clock 发布者。

Q: 力传感器读数 NaN/Inf?
A: 驱动未正常启动; 检查 USB 连接; 运行驱动诊断脚本。

Q: 相机过曝/过暗?
A: 固定曝光; 真实环境需补光 (仿真光照完美)。

Q: npz 格式与仿真不兼容导致 Dataset 报错?
A: 比对 npz keys。必须包含 "frames", "forces", "velocities",
   "contact_states_gt", "contact_states_auto" 及任务 proprio 字段,
   维度一致 (forces 为真实接触力, 实机为腕部 F/T 去零偏后的读数)。

Q: 采集到一半崩溃, 机械臂停在半路?
A: 采集循环 try-finally 安全回位; 或用 action server 的 preempt。

Q: 不同传感器时间戳偏差过大 (>200ms)?
A: 检查 chrony/NTP; 各节点同机运行; 事后补偿固定偏移。
